Finn is an AI companion that lives in iMessage. It handles real-time conversation through a hot-path agent, delegates longer work to background workers, runs saved Patterns for scheduled or trigger-driven automations, and stores runtime state in Finn's own Postgres-backed systems.

The product is opinionated in two ways:

1. It is built to feel like texting a person, not operating a dashboard.
2. It is built as a runtime system, not just a prompt wrapper.

That means the docs need to cover both the user-facing behavior and the machinery behind it. This site is organized around that split.

## What Finn Actually Is

At runtime, Finn is a Bun monorepo with these major pieces:

- A Hono server that receives webhooks, serves files, hosts the web app API, and wires the system together.
- A hot-path agent that handles incoming messages in real time.
- Background workers that do longer or tool-heavy tasks.
- A Pattern scheduler plus Pattern workers for saved automations.
- Finn Puter, a paired Mac app that lets Personal Intelligence inspect local iMessage and Notes through live commands.
- A compactor that keeps the hot-path prompt inside context limits.
- A Postgres database for operational state.
- Inbuilt profile, conversation, file, worker, connector, and Pattern systems.
- Optional integrations for search, media generation, connected SaaS tools, speech, and MCP servers.

Although Finn is framed as a personal AI companion, the server can manage multiple isolated user runtimes behind the same deployment. Each user gets their own profile, conversations, workers, patterns, connectors, and files.

## System Snapshot

```text
iMessage <-> Spectrum <-> Hono server
                           |
                           +-> hot-path ingress coordinator
                           |
                           +-> hot-path agent
                           |     |
                           |     +-> hot-path tools
                           |     +-> user profile + chapter history
                           |     +-> compactor checks
                           |
                           +-> worker manager
                           |     |
                           |     +-> worker agents
                           |     +-> Composio / Exa / Fal / MCP / exec / files / skills
                           |
                           +-> web API and admin API
                           |
                           +-> Puter live bridge <-> Finn Puter Mac app
                           |
                           +-> file routes and public assets

Postgres stores operational state and durable user context.
```
